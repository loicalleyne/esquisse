**ISSUE-C5: Security regression — reports silently moved from gitignored to git-tracked**

- Attack vector: Attack 3 (Security Adversary)
- Description: The current MCP code writes reports to `.adversarial/reports/`. `.adversarial/` is in `.gitignore` (confirmed). P3-008 proposes changing the output path to `docs/adversarial/{slug}/`. `docs/` is NOT gitignored. This silently migrates all new adversarial review reports from ephemeral, private local storage into the tracked repository. Review reports may contain: identified security weaknesses in implementation plans, unverified API assumptions, strategy details about upcoming features, internal critique of the codebase. None of this should be committed to a public git history. The plan does not mention this design consequence anywhere — not in the Goal, not in the Session Notes, not in Acceptance Criteria.
- Evidence: `.gitignore` line 28: `.adversarial/`. `docs/` is not listed in `.gitignore`.
- Impact: Any project using this framework after P3-008 ships will begin committing adversarial review reports to git on every review run via the MCP server. This is irreversible once pushed.
- Required fix: Either (a) add `docs/adversarial/` to `.gitignore` and document this as a required step, or (b) keep reports under `.adversarial/` (change the path to `.adversarial/{slug}/` instead of `docs/adversarial/{slug}/`), or (c) explicitly document the design decision to make reports public and add it to the task's In Scope description. The choice must be explicit and deliberate.

## Uncovered Scenarios

- **Migration of existing `.adversarial/reports/` files**: After P3-008 changes the MCP write path, existing reports under `.adversarial/reports/` become orphaned. No migration step, no documentation of the transition. Future `list_dir` calls in the new path (used by P3-010 Step 5) will miss all historical reports.

- **`writeReportFile` called with `reportsDir` that includes the slug**: After P3-008, `reportsDir` is set to `docs/adversarial/{slug}` before the round loop. But `os.MkdirAll` is called with this new per-slug path. The existing comment above the `MkdirAll` call says "Ensure .adversarial/reports/ exists so the reviewer model can write report files" — this comment will be stale and should be updated.

- **`wc -l` acceptance criterion in P3-010 is fragile on Windows**: The `wc -l` command is not available on native Windows. If the implementer uses a Windows Git Bash or CMD prompt, this criterion silently passes (returns 0 lines) or fails with an error. The acceptance criterion should use a cross-platform check or note the Linux/WSL requirement.

- **P3-010 §3 planner-fixes artifact path uses `docs/adversarial/{slug}/`**: This depends on P3-008's report nesting work (which puts reports in `docs/adversarial/{slug}/`). If P3-008's path is fixed to remain under `.adversarial/`, the planner-fixes artifact path in P3-010 must be updated consistently. P3-010 carries a transitive dependency on whatever P3-008 resolves to.

## Verdict Summary

P3-008 is built against a version of `adversarial.go` that does not exist in the current codebase: the `writeReportFile` signature, the `reportsDir` assignment, the `reviewPromptTemplate` constant, and the `params.PlanSlug` variable are all phantom references. Additionally, P3-008's path change silently moves audit artifacts from gitignored to git-tracked storage — a security regression not mentioned anywhere in the plan. P3-009 uses an unverified VS Code tool ID format and violates an AGENTS.md invariant without acknowledgment. These issues are not cosmetic — they block implementation entirely. The plan cannot be implemented as written.

Verdict: FAILED
